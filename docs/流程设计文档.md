> **版本**: v1.0

## 1. 系统架构总览

### 1.1 技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| **前端** | HTML5 + CSS3 + JavaScript + SSE | 轻量前端，无需框架，兼容性好 |
| **后端** | Python 3.11+ + FastAPI | 高性能异步 Web 框架 |
| **流程编排** | LangGraph | 状态机驱动，支持复杂流程 |
| **向量检索** | Milvus 2.4+ | 混合检索（稠密+稀疏向量） |
| **历史存储** | MongoDB 6.0+ | 对话记录、用户信息 |
| **对象存储** | MinIO | 仅存储文档中的图片（通过URL访问） |
| **文档解析** | MinerU | PDF/PPT/DOCX 多格式解析 |
| **大语言模型** | OpenAI 兼容 API | 通用 LLM + 视觉模型 |
| **嵌入模型** | BGE-M3（本地） | 稠密+稀疏向量化 |
| **重排序模型** | BGE-Reranker（本地） | Cross-Encoder 精排 |
| **联网搜索** | DashScope MCP | 百炼平台 WebSearch |
| **认证** | JWT (python-jose) | 用户身份验证 |

## 2. 用户认证与权限流程

### 2.1 权限模型

系统仅包含两种权限：**导入权限** 和 **查询权限**

| 权限类型 | 说明 | 对应接口 |
|----------|------|----------|
| **导入权限** | 允许上传文档到知识库 | `/api/import/*` |
| **查询权限** | 允许使用问答功能查询知识库 | `/api/query/*` |

> **注意**：所有用户必须登录后才能使用系统。登录用户可在创建时指定是否拥有导入权限。

### 2.2 用户类型

| 用户类型 | 登录 | 查询 | 导入 | 说明 |
|----------|------|------|------|------|
| **普通用户** | ✅ | ✅ | ❌ | 仅可查询知识库（如学员） |
| **导入用户** | ✅ | ✅ | ✅ | 可导入文档 + 查询（如助教、教师） |

### 2.3 认证流程

```
用户访问系统 → 前端检查本地 Token
    │
    ├── Token 有效 → 直接进入主页（chat.html）
    │
    └── Token 无效/过期 → 跳转登录页（login.html）
         │
         ▼
         用户输入账号密码 → POST /api/auth/login
         │
         ▼
         后端验证用户名密码（MongoDB users 集合）
         │
         ▼
         生成 JWT（含 username, can_import 字段）
         │
         ▼
         返回 Token → 前端存储到 localStorage
         │
         ▼
         跳转到主页（chat.html）
         
用户后续请求：
    - 查询接口：携带 Token，验证登录状态即可
    - 导入接口：携带 Token，验证登录状态 + can_import=true
```

### 2.4 JWT Token 结构

```json
{
  "sub": "user_id",
  "username": "zhangsan",
  "can_import": true,
  "iat": 1686873600,
  "exp": 1686960000
}
```

**字段说明**：
- `sub`: 用户唯一ID
- `username`: 用户名
- `can_import`: 布尔值，`true` 表示拥有导入权限，`false` 表示仅可查询
- `iat`: 签发时间
- `exp`: 过期时间（默认24小时）

### 2.5 认证中间件设计

```python
# app/shared/auth/middleware.py
from fastapi import Request, HTTPException, Depends
from fastapi.security import HTTPBearer
from app.shared.auth.jwt_utils import decode_token

security = HTTPBearer()

async def get_current_user(request: Request) -> dict:
    """验证 JWT 并返回用户信息"""
    try:
        token = await security(request)
        payload = decode_token(token.credentials)
        if not payload:
            raise HTTPException(status_code=401, detail="Token 无效或已过期")
        return payload
    except Exception:
        raise HTTPException(status_code=401, detail="认证失败")

def require_import_permission(user: dict = Depends(get_current_user)) -> dict:
    """校验导入权限"""
    if not user.get("can_import"):
        raise HTTPException(status_code=403, detail="无导入权限，请联系管理员开通")
    return user
```

**使用示例**：

```python
# 查询接口：仅需登录
@app.post("/api/query")
async def query(user: dict = Depends(get_current_user)):
    pass

# 导入接口：需要导入权限
@app.post("/api/import/upload")
async def upload(user: dict = Depends(require_import_permission)):
    pass
```

### 3.4 导入进度追踪（带百分比）

```python
# app/shared/utils/task_utils.py
def task_push_queue(task_id: str, status: str, done_list: list, running_list: list):
    """推送任务进度到 SSE 队列"""
    total_nodes = 7  # 导入流程固定7个节点
    done_count = len(done_list)
    percentage = int((done_count / total_nodes) * 100)
    
    queue_data = {
        "status": status,
        "done_list": done_list,
        "running_list": running_list,
        "progress_percentage": percentage,  # 新增百分比字段
        "timestamp": time.time()
    }
    task_status_queue[task_id].put(queue_data)
```

## 4. 查询流程

### 4.1 整体流程图

```
┌─────────────────────────────────────────────────────────────────┐
│                      查询流程（8个节点）                          │
└─────────────────────────────────────────────────────────────────┘

  用户输入问题 → POST /api/query → 生成 session_id → 订阅 SSE
       │
       ▼
  ┌─────────────────────────────────────────────────────────┐
  │         node_history_match（历史答案匹配 - 新增）         │
  │  - 获取当前会话历史问题列表                              │
  │  - 计算问题相似度（BGE-M3 稠密向量）                     │
  │  - 阈值 > 0.95：直接返回历史答案                        │
  │  - 阈值 <= 0.95：继续后续流程                            │
  │  - 校验历史答案时效性（文档更新时间对比）                │
  └─────────────────────────────────────────────────────────┘
       │
       ▼
  ┌─────────────────────────────────────────────────────────┐
  │        node_item_name_confirm（主体名称确认）             │
  │  - 结合历史对话，LLM 提取主体名称 + 问题重写             │
  │  - 主体名称向量化 → Milvus 查询确认                     │
  │  - 三种状态：                                           │
  │    a) 确认列表 > 0 → 直接走检索流程                     │
  │    b) 确认=0 但可选列表 > 0 → 返回可选列表（前端交互）  │
  │    c) 确认=0 可选=0 → 降级到网络搜索                    │
  └─────────────────────────────────────────────────────────┘
       │
       ▼
  ┌─────────────────────────────────────────────────────────┐
  │              条件路由（基于主体确认结果）                  │
  │                                                         │
  │  case 确认列表有值:                                      │
  │      → 并发三路检索（embedding + hyde + web）           │
  │                                                         │
  │  case 可选列表有值:                                      │
  │      → 返回 answer（前端展示可选列表）                  │
  │      → 用户点击后二次请求，携带 confirmed_item_names     │
  │      → 跳过 node_item_name_confirm，直接进入检索        │
  │                                                         │
  │  case 都没有:                                            │
  │      → 设置 fallback_to_web=True                        │
  │      → 仅执行 node_web_search_mcp                       │
  └─────────────────────────────────────────────────────────┘
       │
       ▼
  ┌─────────────────────────────────────────────────────────┐
  │              并发三路检索（可独立开关）                    │
  │                                                         │
  │  ├─ node_search_embedding（标准向量检索）                │
```

### 6.3 接口设计

#### 6.3.1 查询接口设计

**请求参数**：
```python
class QueryRequestParam(BaseModel):
    query: str                      # 用户问题（必填）
    session_id: str                 # 会话ID（可选，不传则自动生成）
    is_stream: bool = False         # 是否流式输出
```

**接口说明**：

**响应参数**：

1. **流式响应（SSE事件）**：

```
┌─────────────────────────────────────────────────────────────┐
│                 主体可点击交互流程                            │
└─────────────────────────────────────────────────────────────┘

  第一次请求：
  用户提问 → node_item_name_confirm → LLM识别主体
       │
       ├── 确认列表>0（>0.7分）→ 直接检索 → 返回答案
       │
       ├── 可选列表>0（0.6-0.7分）→ 返回 need_confirm=True
       │                               返回 options_item_names
       │                                    ↓
       │                           前端渲染可点击列表
       │                                    ↓
       │                           用户点击某个主体
       │                                    ↓
       └── 都没有 → 返回 fallback_to_web  → 降级网络搜索

  第二次请求（用户点击后）：
  用户点击主体 → 携带 confirmed_item_names → skip_item_confirm=True
       │
       ▼
  node_item_name_confirm（跳过）
       │
       ▼
  直接进入 node_search_embedding（检索流程）
       │
       ▼
  返回答案
```

#### 6.3.3 历史滞后校验流程

```
┌─────────────────────────────────────────────────────────────┐
│                 历史滞后校验流程                             │
└─────────────────────────────────────────────────────────────┘

  用户提问 → node_history_match → 获取历史问题列表
       │
       ▼
  计算问题相似度（向量化+BGE-M3）
       │
       ├── 相似度 > 0.95
       │       │
       │       ▼
       │   获取最新文档导入时间戳
       │   history_repository.get_latest_import_timestamp()
       │       │
       │       ├── 历史答案时间 >= 文档更新时间
       │       │       → 答案有效，直接返回
       │       │
       │       └── 历史答案时间 < 文档更新时间
       │               → 答案已滞后，继续后续流程
       │
       └── 相似度 <= 0.95 → 继续后续流程
```

**关键判断逻辑**：
```python
def validate_history_answer时效性(candidate_answer_ts: float, latest_import_ts: float) -> bool:
    """
    校验历史答案是否已滞后
    :param candidate_answer_ts: 历史答案的时间戳
    :param latest_import_ts: 文档最新更新时间戳
    :return: True=答案有效可直接返回，False=答案滞后需重新检索
    """
    # 若文档在答案生成后有更新，则答案已滞后
    if latest_import_ts > candidate_answer_ts:
        return False
    return True
```

```python
# app/rag/query/item_name_confirm_service.py
def select_item_names(milvus_result_dict):
    """
    根据Milvus查询结果，生成确认列表和可选列表
    - confirmed_item_name_list：>0.7分，确定性高
    - options_item_name_list：0.6-0.7分，需要用户确认
    """
    confirmed_item_name_list = []
    options_item_name_list = []
    
    for item_name, milvus_list in milvus_result_dict.items():
        milvus_list.sort(key=lambda x: x['score'], reverse=True)
        
        # 确认列表：分数>0.7
        high_item_names = [item['item_name'] for item in milvus_list if item['score'] > 0.7]
        # 可选列表：分数0.6-0.7
        md_item_names = [item['item_name'] for item in milvus_list if 0.6 < item['score'] <= 0.7]
        
        if len(high_item_names) > 0:
            confirmed_item_name_list.append(high_item_names[0])
        elif len(md_item_names) > 0:
            options_item_name_list.extend(md_item_names[:2])  # 最多2个选项
    
    return {
        "confirmed_item_name_list": confirmed_item_name_list,
        "options_item_name_list": options_item_name_list
    }

def change_state_status(state, item_name_dict, rewritten_query):
    """
    修改状态：支持用户点击确认的主体
    """
    confirmed_list = item_name_dict.get('confirmed_item_name_list', [])
    options_list = item_name_dict.get('options_item_name_list', [])
    
    # 场景1：确认列表有值（>0.7分），直接进入检索
    if confirmed_list and len(confirmed_list) > 0:
        state['item_names'] = confirmed_list
        state['rewritten_query'] = rewritten_query
        return
    
    # 场景2：可选列表有值（0.6-0.7分），返回前端让用户点击
    if options_list and len(options_list) > 0:
        state['options_item_names'] = options_list
        state['need_confirm'] = True
        state['rewritten_query'] = rewritten_query
        # 不设置answer，通过SSE事件返回给前端
        return
    
    # 场景3：都没有，降级到网络搜索
    state['fallback_to_web'] = True
    state['rewritten_query'] = rewritten_query

# app/process/query/agent/main_graph.py
def node_item_name_confirm_after(state: QueryGraphState):
    """条件路由：支持用户点击确认的主体"""
    # 用户二次请求，跳过确认节点
    if state.get("skip_item_confirm") and state.get("confirmed_item_names"):
        state['item_names'] = state['confirmed_item_names']
        return "node_search_embedding", "node_search_embedding_hyde", "node_web_search_mcp"
    
    # 有确认的主体
    if state.get("item_names"):
        return "node_search_embedding", "node_search_embedding_hyde", "node_web_search_mcp"
    
    # 需要用户确认
    if state.get("need_confirm"):
        return "node_answer_output"
    
    # 降级到网络搜索
    if state.get("fallback_to_web"):
        return "node_web_search_mcp"
    
    return "node_answer_output"
```

```python
import hashlib

def calculate_file_hash(file_path: str) -> str:
    """计算文件 SHA256 哈希"""
    sha256 = hashlib.sha256()
    with open(file_path, "rb") as f:
        for chunk in iter(lambda: f.read(8192), b""):
```
